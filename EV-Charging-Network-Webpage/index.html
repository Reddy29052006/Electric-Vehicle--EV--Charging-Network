PART 1 : PROBLEM STATEMENT, CLASSES & OBJECTS, ENCAPSULATION & COLLECTIONS

1.1 REAL-TIME PROBLEM STATEMENT

  • Rapid growth of EV's leads to unorganized charging infrastructure.
  • Issues like long queues, double-booking of connectors & no proper billing.
  • Need: A system to manage, book, monitor & bill EV charging in an organized way.
  • Solution: EV Charging Network System using Java OOPs.

1.2 CLASSES & OBJECTS

  • Class - Blueprint (e.g., ChargingStation)
  • Object - Real instance created in Main.java
  • We created objects like station1, fastStation1 to perform actions.

1.3 ENCAPSULATION

  • All important data members in ChargingStation are declared private.
  • Access is given only through getters & setters.
  • Example: stationId, availablePower, ratePerKWh, connectorStatuses.
  • Purpose: Data hiding & controlled access.

1.4 COLLECTIONS (ARRAYLIST)

  • Used ArrayList<String> connectorStatuses to maintain real-time status.
  • Initialized with "Available" for each connector.
  • On occupyConnector() -> updated to "Occupied".
  • On releaseConnector() -> updated back to "Available".
  • Also shown: trim() & toUpperCase() used to format Station IDs.

PART 2 : INHERITANCE, ABSTRACTION, POLYMORPHISM, INTERFACE & EXCEPTION HANDLING

2.1 INHERITANCE

  • FastChargingStation extends ChargingStation.
  • Uses super() to call parent constructor.
  • Reuses occupyConnector(), releaseConnector(), exportInvoice().
  • Adds its own property - fastChargingRate.

2.2 ABSTRACTION & INTERFACE

  • Implemented BillablePower interface in ChargingStation.
  • Defines contract: getRatePerKWh(), setRatePerKWh(), calculateBill(), exportInvoice().
  • Hides "how billing works" and shows only "what is needed".
  • Normal rate - $12.50/kWh, Fast Charging rate - $18.00/kWh.

2.3 POLYMORPHISM

  • Method Overriding: toString() overridden in FastChargingStation.
  • exportInvoice() works with parent reference but executes based on object.
  • Same method name gives different behavior depending on object type.

2.4 EXCEPTION HANDLING (CUSTOM EXCEPTIONS)

  • ConnectorInUseException - Double-booking of same connector.
  • ConnectorOccupiedException - Booking an already occupied connector.
  • ConnectorAvailableException - Releasing an already available connector.
  • InvalidConnectorException - Invalid connector index.
  • InvalidPowerException - Power out of range.
  • InvalidChargingRateException - Invalid fast charging rate.

PART 3 : FILE I/O, MULTITHREADING, LAMBDA & STREAMS

3.1 FILE I/O (INVOICE GENERATION)

  • Invoices are written to charging_bills.txt using FileWriter, BufferedWriter & PrintWriter.
  • Appended using new FileWriter(file, true).
  • Stores Station ID, Connector ID, Energy Consumed, Tariff, Total Amount, Date & Time.
  • Automatically exported on charging session completion.

3.2 MULTITHREADING

  • ChargingSession implements Runnable.
  • Background thread created using new Thread(session).start().
  • Battery % updates every 2 seconds using Thread.sleep(2000).
  • Normal: +10% per update | Fast: +20% per update.
  • thread.join() used in Main to wait till completion.

3.3 LAMBDA EXPRESSION & STREAMS

  • Collected all stations in ArrayList<ChargingStation>.
  • Used stream().filter(station -> station.getAvailablePower() > 50.0f) with Lambda.
  • Filtered only stations having available power > 50kW.
  • Displayed using forEach().

CONCLUSION

FINAL CONCLUSION

We have successfully implemented the Electric Vehicle (EV) Charging Network System by applying all the core Object Oriented Programming concepts. This project demonstrates how real-time problems can be solved using Classes & Objects, Encapsulation, Inheritance, Abstraction, Polymorphism, Interface, Exception Handling, Collections, File I/O, Multithreading, Lambda Expressions & Streams. This system helps in managing EV charging in an efficient, organized and automated manner.
